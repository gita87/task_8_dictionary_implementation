# Architecture

Production Python lives in `src/`. `qaos_dictionary` is the conversion library;
`app` is the optional Flask adapter. Root `cli.py`, `dict_docx_to_csv.py`, and
`wsgi.py` retain existing launch commands. Install the project before running them.
The console entry point is `qaos_dictionary.cli:main`.

```text
CLI / Flask
    → pipeline (workflow, result, progress/cancellation checkpoints)
        → source (bounded input, ZIP and XML preflight)
        → extraction (table selection, plain text, generated IDs)
            → images (embedded bytes → WebP URI)
        → serialization (dictionary validation → shared CSV writer)
    → app.qa (shared CSV reader, report)
```

`models` owns API dataclasses, input/callback types and diagnostic adapters.
`contracts` owns consumer constants; shared schema and limits come from
`qaos_common`. `operations` adapts legacy progress/cancellation behavior.
`core` is an import compatibility facade with no processing logic.

The conversion boundaries import neither Flask nor the CLI. They do not make
network calls, publish files, open browsers, or mutate global CSV parser limits.
The CLI owns atomic publication, while Flask returns generated bytes. Common
owns dictionary schema, profile, generic CSV validation/I/O, and shared operation
contracts. DOCX table rules, ID formatting, WebP encoding, ZIP/XML preflight, and
nonempty definitions belong here.

Conversions materialize the bounded input, DOCX tree, extracted rows, and output.
This is not a streaming DOCX engine. Cancellation is cooperative between stages
and rows; an in-progress Pillow encode cannot be interrupted. A service handling
untrusted concurrent jobs needs process/resource/time limits at deployment.

Tests exercise public behavior, golden bytes and adversarial boundaries. Test
patches now target the owning module rather than `core` implementation globals.
Only published names and documented callbacks are compatibility commitments.

`mypy` strict checks all of `src`, including Flask adapters and packaged shims.
Ruff checks Python throughout the repository except the exploratory notebook
sandbox. Branch coverage covers both the library and Flask adapter, with an
85% aggregate floor. No production module is omitted to meet that floor.
